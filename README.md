## How I Build

I value software that is:

* **Useful** — solves a clearly defined problem.
* **Understandable** — users should not need technical knowledge to use it.
* **Maintainable** — the system should remain understandable as it grows.
* **Practical** — technology should serve the problem, not the other way around.
* **Adaptable** — products should evolve based on real user needs.
* **Reliable** — a working product matters more than an impressive demonstration.

I am less interested in building software simply to demonstrate that I can use a technology.

I am more interested in **what can be built with it and who it can help**.
